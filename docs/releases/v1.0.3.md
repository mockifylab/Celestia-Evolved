# What is new in 1.0.3

This release is about responsiveness. The settings window, the sliders and the
shell around them all spent less time working on screen.

## Appearance settings open instantly

The Appearance page used to build a menu entry for every font family installed
on the system, twice, while the page opened. On a machine with a full TeX or
Nerd Fonts install that is several thousand objects, and the shell stopped
answering for seconds at a time.

The family list is now read the first time you actually open a font row, each
row builds only its own list, and the open menu creates just the entries it can
show, scrolling for the rest. Menus are also capped to the height of the panel
they float in, so a long list no longer pushes off screen.

Measured in an isolated session on the same machine: navigation involving the
Appearance page blocked the shell for four to eight seconds before, and now
returns in about a fifth of a second.

## Sliders stop fighting the frame rate

A drag produces one value per pointer sample, and every one of those values used
to be written through to the setting behind it. Sliders now send one write per
forty milliseconds while you drag, and always send the value you released on, so
the setting ends up exactly where you left it. The handle and the filled track
still follow the pointer on every frame, so nothing feels rubber-banded.

The volume slider in the bar does the same for the audio server, and the
transparency slider no longer rebuilds the compositor's blur rules about
thirty-three times a second: the rules are re-applied a quarter of a second
after the value settles, and only when they actually change.

## Wallpaper previews do less work

Scrolling the wallpaper list used to decode an image and regenerate a full
colour palette for every row you passed. Previews still change immediately, but
the colour analysis now runs once, on the wallpaper you settle on. A palette
that arrived for a preview you already closed no longer brings it back.

## Workspace tracking

Matching a window against the ignored-tag list no longer compiles a regular
expression per window per compositor event.

## Updates

- When the newest release is already installed, the Updates page says so in
  plain words instead of offering the same download again.
- If the running build and the installed release differ, the page shows the
  running build so it is obvious why a restart is still needed.
- Release notes are shown as clean prose in the app. Published notes are written
  by hand for each release instead of being generated by GitHub, so they read as
  a summary of what you can now do.

## For developers

The release pipeline now takes its notes from `docs/releases/<tag>.md` and keeps
the updater's checksum marker on the first line. Slider throttling and release
note rendering are covered by fixtures: `tests/sliders/run-mapping-test.sh` and
`tests/updater/run-notes-fixture.sh`.
