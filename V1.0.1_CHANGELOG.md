## [1.0.1] — maintenance (in progress)

### Fixed
- (Phase 1) VERIFIED `ce826234` — notification popups are a configurable panel:
  placement (6 positions), width and max-height settings; region masks and hover
  boundaries adapt to placement. Gates: build, qmllint, conventions, format.
- (Phase 2) VERIFIED `b2191890` — SliderRow maps StyledSlider's normalized
  interaction position to the control's actual value range (step-snapped, clamped);
  fixes all non-0..1 sliders (appearance/motion/hyprland).
- (Phase 3) VERIFIED `12d7fc60` — wallpapers persist via FileView write to state
  path (survives restart/reboot, no `caelestia` CLI needed); dominant colour and
  full palette derived in-shell via ImageAnalyser → ColorGen; scheme.json fallback
  to wallpaper-derived palette; built-in custom palette default for fresh installs.
- (Phase 4) VERIFIED `36f54373` — light/dark/auto mode fully applied: auto resolves
  from wallpaper luminance and re-evaluates on wallpaper change; mode toggling
  propagates through Colours.palette bindings.
- (Phase 5) VERIFIED — app icon fallback changed from `image-missing` to
  freedesktop `application-x-executable` in all 5 icon-resolution sites; verified
  present in installed themes (Adwaita/breeze/Qogir) and 40/40 sampled installed
  desktop-entry icons resolve on this system.
- (Phase 7) VERIFIED — Hyprland settings page now reads and writes the real
  compositor state. Root causes fixed in `HyprExtras`:
  1. `refreshOptions` parsed the pre-0.55 descriptions schema (`value`/`data.current`),
     so 0.56's `{name, current}` yielded an empty options map — dual-schema parse now.
  2. descriptions `current` truncates floats (0.93→0) and reports stale bools — an
     authoritative `[[BATCH]]j/getoption <k>` pass now overwrites every value.
  3. large socket replies arrive chunked and the old per-chunk callback fed partial
     JSON to the parser — new `makeAccumulatedRequest` buffers until end-of-response
     (Hyprland closes/half-closes after writing; `PeerClosedError` with buffered data
     is treated as normal completion).
  4. `applyOptions` lua branch emitted unquoted string values (`eval hl.config` rejected
     them) — strings are now quoted/escaped.
  QML fixes (`HyprlandPage.qml`): `[[EMPTY]]` placeholder treated as default; css-typed
  values ("4 4 4 4") read as leading number; accel_profile handled as string enum
  (Default ""/adaptive/flat/legacy) not int; workspace sensitivity slider range
  corrected to Hyprland's -1..1 (was 0.1..2, out of valid range). `GameMode.qml`
  `=== 0` int check made bool-safe via `Number(...) === 0`.
  Live-verified on running Hyprland 0.56.2: 353 options with correct values
  (opacity 0.93, gaps "4 4 4 4", bools accurate) and a full `applyOptions` round-trip
  of a string option ("flat" applied, then restored). Side effects of testing on the
  live session, flagged for honesty: `input:accel_profile` is now explicitly set to ""
  (functionally identical to the previous unset default), and
  `gestures:workspace_swipe_create_new` was re-set to its true value (set-flag flipped).
  Legacy (non-lua) apply path is code-correct but not live-testable on this lua-mode
  session.

### Added
- (Phase 1) VERIFIED `ce826234` — Notification placement and size settings
  (NotifPlacement enum + width/maxHeight in notifsconfig; UI in NotificationsPage).
- (Phase 6) VERIFIED — window minimize/restore. Hyprland 0.56.2 (this system) has
  no `minimize` dispatcher (verified live: lua `hl.dsp.window.minimize` nil, docs
  contain no minimize); implemented the wiki-sanctioned special-workspace approach:
  `Hypr.minimizeWindow/restoreWindow/focusOrRestore` park windows in
  `special:minimized` and remember their origin workspace. Minimize/Restore button
  in the window-info panel; bar taskview icons are now clickable (focus/restore)
  and dim (opacity 0.4) while minimized. Never kills anything; restore uses
  move+follow. Live-verified both directions on a disposable scratch window
  (lua branch; legacy branch kept for pre-lua Hyprland but not live-testable here).
- (Phase 8) VERIFIED — genuine in-app update interface. The Updates page binds
  the real state machine in `services/Updater.qml` (GitHub Releases feed of
  mockifylab/Celestia-Shell_Reimagend; installed version comes from the build's
  embedded `CUtils.version`, no fake constants). Added `feedOverride` (init from
  `CAELESTIA_UPDATE_FEED`) so the flow is testable/self-hostable without
  weakening the safety chain: download -> SHA-256 verify -> extract -> apply
  with backup and rollback via `assets/update/apply_update.sh`.
  New `tests/updater/run-qml-fixture.sh` drives the REAL singleton offscreen
  under quickshell against a localhost fixture feed and asserts the full
  machine end-to-end (12 checks): dead feed -> clean error, available
  (version compare 1.0.0 vs 1.0.1 + digest/notes parse), download/verify/
  staging/applying/applied, install dir updated, user data preserved, rollback
  env written. Original helper fixture still passes (23 checks).
  NOT verifiable offline (honest note): a live check against the real GitHub
  feed and an actual release asset — the repo has no published releases yet and
  pushing/releasing is prohibited; the wire format is verified via the
  GitHub-shaped fixture instead.
- (Phase 9) VERIFIED — Developer section in the About page. Added a "Developer"
  group with the developer name "Aasif" and a "View on GitHub" button that opens
  https://github.com/mockifylab via `Qt.openUrlExternally` (the app's established
  link mechanism, same as notification links). The About page is wired into both
  PageRegistry (label "About") and PageCompRegistry (AboutPage), so the section is
  reachable in the running shell. Verified statically: qmllint resolves ButtonRow,
  IconTextButton and the `IconTextButton.Tonal` enum with zero output; the exact
  ButtonRow+IconTextButton+onClicked construct already renders in the shipped
  Updates page. NOT verifiable offline (honest note): the physical browser launch
