- (Phase 3) VERIFIED `12d7fc60` — wallpapers persist via FileView write to state

  full palette derived in-shell via ImageAnalyser → ColorGen; scheme.json fallback
  to wallpaper-derived palette; built-in custom palette default for fresh installs.
- (Phase 4) VERIFIED `36f54373` — light/dark/auto mode fully applied: auto resolves

- (Phase 5) VERIFIED — app icon fallback changed from `image-missing` to
  freedesktop `application-x-executable` in all 5 icon-resolution sites; verified
  present in installed themes (Adwaita/breeze/Qogir) and 40/40 sampled installed
  desktop-entry icons resolve on this system.
- (Phase 7) VERIFIED — Hyprland settings page now reads and writes the real
  compositor state. Root causes fixed in `HyprExtras`:
  1. `refreshOptions` parsed the pre-0.55 descriptions schema (`value`/`data.current`),
     so 0.56's `{name, current}` yielded an empty options map — dual-schema parse now.
  2. descriptions `current` truncates floats (0.93→0) and reports stale bools — an
     authoritative `[[BATCH]]j/getoption <k>` pass now overwrites every value.
  3. large socket replies arrive chunked and the old per-chunk callback fed partial
     JSON to the parser — new `makeAccumulatedRequest` buffers until end-of-response
     (Hyprland closes/half-closes after writing; `PeerClosedError` with buffered data
     is treated as normal completion).
  4. `applyOptions` lua branch emitted unquoted string values (`eval hl.config` rejected
     them) — strings are now quoted/escaped.
  QML fixes (`HyprlandPage.qml`): `[[EMPTY]]` placeholder treated as default; css-typed
  values ("4 4 4 4") read as leading number; accel_profile handled as string enum
  (Default ""/adaptive/flat/legacy) not int; workspace sensitivity slider range
  corrected to Hyprland's -1..1 (was 0.1..2, out of valid range). `GameMode.qml`
  `=== 0` int check made bool-safe via `Number(...) === 0`.
  Live-verified on running Hyprland 0.56.2: 353 options with correct values
  (opacity 0.93, gaps "4 4 4 4", bools accurate) and a full `applyOptions` round-trip
  of a string option ("flat" applied, then restored). Side effects of testing on the
  live session, flagged for honesty: `input:accel_profile` is now explicitly set to ""
  (functionally identical to the previous unset default), and
  `gestures:workspace_swipe_create_new` was re-set to its true value (set-flag flipped).
  Legacy (non-lua) apply path is code-correct but not live-testable on this lua-mode
  session.
- (Phase 10) VERIFIED — Settings UI consistency/labeling polish (no behavior change).
  Scope chosen by the user: "Consistency sweep" + "Accessibility & labels".
  1. Empty-value placeholder markers unified to the house em-dash `—`. AboutPage
     used `…` for 5 rows while the network detail pages already used `—`; all About
     placeholders normalized to `—`. Repo-wide grep confirms zero remaining `…`
     used as an empty-value placeholder (the remaining `…` are legitimate progress
     ellipses inside translatable strings, e.g. "Checking for updates…").
  2. Real correctness fix in UpdatePage.qml "Installed" row: the guard
     `value: `v${Updater.currentVersion}` || "…"` was dead code — a template literal
     is always truthy, so the fallback could never render and an unset version
     showed as "v". Now `Updater.currentVersion !== "" ? `v${...}` : "—"`, matching
     the adjacent "Latest" row. Swept every settings page for the same template-
     literal-with-`||`-fallback anti-pattern; no other instances exist.
  3. Connected-row `first`/`last` boundary audit across all 38 nexus pages: no
     defects. A leading `SectionHeader { first: true }` is the intended house
     pattern (SectionHeader.qml uses it to suppress the top margin on the page's
     first card); `first`/`last` count imbalances are explained by that header and
     by self-closing components (e.g. AudioDeviceList sets `last: true` internally),
     not by missing markers.
  Accessibility: the codebase uses no Qt Quick `Accessible.*` property convention
  anywhere (only WlrKeyboardFocus input grabs), so introducing ARIA-style names
  would be new, inconsistent behavior and is out of the no-behavior-change scope;
  "labels" was therefore addressed via visible-label/placeholder consistency.
  Gates: build PASS, conventions PASS (291 files, zero violations), qmlformat
  byte-equality on both changed files, qmllint zero-output on all 14 owned files
  (CI-exact buildDir/importPaths from regenerated .qmlls.ini).
- (Phase 11) VERIFIED — Performance & reliability audit; found and fixed real
  latent CI-breaking defects in the Phase 7 C++ (commit bdeaf557):
  1. clang-format version-drift: `QStringList types { ... }` brace spacing is
     formatted differently by LLVM 23 vs older releases; switched to the
     version-stable `= { ... }` copy-init idiom already used upstream
     (lyrics.cpp), so check-cpp passes on any toolchain.
  2. clang-tidy (LLVM 23, `-warnings-as-errors='*'`): 8 errors in my code —
     static-constant naming (k_types), misc-const-correctness (buffer/done/
     finish), four unused explicit `this` captures in the socket lambdas.
     All fixed; the full repo (65 real TUs) now passes a CI-faithful
     run-clang-tidy with exit 0.
  3. Runtime audit in an isolated nested-Hyprland session (wayland-2, own XDG
     dirs, live desktop untouched): clean startup — zero errors/warnings, no
     duplicate shell processes, no binding loops; background/drawers/exclusion
     layers all mapped; screenshot evidence retained.
  Environment finding (not a repo defect): Arch's qt6-base ships no WebP codec
  (moved to the separate qt6-imageformats package), so the bundled
  assets/wallpaper.webp logged decode warnings; installed qt6-imageformats —
  warnings gone on next boot. The repo also legitimately requires it (upstream
  nix flake bundles webp).
